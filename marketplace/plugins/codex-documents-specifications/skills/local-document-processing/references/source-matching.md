# Match existing document extracts

Read when locating or assessing an existing Markdown extract before conversion or specification work. This workflow is read-only.

Choose a bounded local index, CLI or native path/metadata inspection that retrieves candidates by recorded source path or SHA-256. Use a compatible MCP when repeated structured access or client restrictions justify it. Verify current options/schema and permitted roots; keep private material local. Missing metadata or hashes limit the result, and lookup does not authorize tool installation or configuration.

| Status | Evidence |
|---|---|
| `current` | Recorded source metadata and SHA-256 agree with the selected original |
| `stale` | Same recorded source path, different source content |
| `candidate` | Filename-only or incomplete metadata match |

Preserve candidate path, recorded source, hash, extraction time and match reasons. Prefer verified identity over filenames. Hash agreement establishes source identity/freshness, not complete extraction, correct OCR/tables or semantic accuracy.

For multiple versions, distinguish original revision time from file modification, download and extraction times. Order verified revisions with their timezone and original precision; retain unknown times. Hashes and newer timestamps do not determine specification authority.

The original PDF, Office file or other source remains authoritative. Start from relevant usable extract sections. Reopen needed original sections for visual evidence, missing or unclear content, stale/conflicting versions, or an explicit original-source check. Distinguish extract-only evidence from inspected originals.

Return the matched candidates and concrete evidence limits. Regeneration, replacement, synchronization and deletion require their own authorized processing scope.
