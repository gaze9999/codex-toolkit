# Source authority and current/history records

Read when documentation conflicts with implementation or when maintaining paired current-state/history files.

## Resolve conflicting evidence

Compare relevant Git history/diffs, document revisions and extract source hashes. Record version, branch/commit, dirty state and verified revision/change time, separating unknown dates. Keep source, modification, download, extraction and verification times distinct. Preserve timezone and source precision; use `yyyy-mm-dd hh:mm` only when supported, retaining date-only evidence as dates.

Governing specifications and confirmed decisions retain authority. Newer timestamps and observed code behavior do not approve a requirement change. Preserve unresolved conflicts and update independent implementation/status sections within scope.

## Maintain existing history

When a current-state document already has paired history/archive, keep current behavior, active work, unresolved decisions and latest verification boundary in the current document. Move superseded status, completed batches, dated execution details, old sync records and obsolete navigation only after preserving unique evidence. Do not create a general history/report merely for an update.

Keep existing IDs stable. An explicitly requested identifier scheme applies to current records with the old-to-new mapping in history; historical IDs/anchors change only when explicitly requested.

Write concise entries containing outcome, material evidence and remaining verification limits. Length follows the information needed; command sequences and check-by-check narration do not belong in routine history. Preserve required existing record formats and unique evidence.
