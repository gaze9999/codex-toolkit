# 通用工作原則中文對照

AI 入口: [AGENTS.md](AGENTS.md)

- 先理解目的、授權、修改範圍與驗收, 讀適用指示及必要來源, 保留使用者與並行工作
- 採最小完整修改, 沿既有架構與工具, 維護不自行擴大重構、改 API 或整份重寫文件
- 自有元件按用途分 Skill、條件式 reference、資產、獨立 core / CLI 與薄 MCP, 細節查所屬維護指引
- 驗證從最小足夠範圍開始, 證據不足才擴大, 回報實際結果、涵蓋範圍與必要待辦
- 回覆依當前介面、工具與格式規格選擇, 一般說明用 Markdown, 比較用表格, 有助探索才用互動, 完成稿才用支援的 writing block. 聊天正文不用 details / summary 等 HTML 排版, 原始碼與引用保留, 不自造 directive 或假按鈕, 格式失效改用可讀 Markdown 或實際成果
- 公開內容不含個人設定、機敏資料或未授權相依, 安裝、帳戶、client 載入與實際呼叫分開確認
- Commit、push、Tag、release 與遠端操作依當次授權, 先核對實際差異並保留他人修改

- Global 與內部工作規範使用精簡英文, 需要時另維護人類語言對照並核對語意, 使用者交付依指定語言, 教學供人與 AI 使用, 寫明前提、輸入、步驟、產物與驗收

- 語意工具只處理尚未釐清的有限判斷, 獲准外部評估時檢查最小通用或合成資料的條件、未知狀態、機敏資訊與語意偏移, 來源對照留在本機, 精確規則用確定性檢查, 抽象評分不代表實作驗收
- 新增或修改敘述優先用本機 textlint CLI 與專案規則, MCP 用於補足能力缺口, 保留來源原文、程式碼與訊息, 並人工複核語意

- 敘述與程式碼註解不使用免責性或防禦性措辭, 方法內有多種判斷、多個變數、回傳分支或狀態互動且名稱與結構不足以說明時才加註解
- 自有識別字原則上由 1–3 個有意義的英文詞組成, 沿用專案大小寫規則, 保留清楚語意、公開 API、框架相容性與外部名稱, 避免難懂縮寫及無關的全面重命名

- 修改回覆以精簡表格列檔案連結、改前、改後、實際影響、檢查結果與問題, 可見工作摘要保持簡單幾行, 依實際工作動態選擇狀態, 分清執行結果、後續補充與未執行待辦, 不固定分類或保留空標題
