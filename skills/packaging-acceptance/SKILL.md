# Packaging Acceptance

Resolve the actual release workflow, source snapshot, target platform and entry points. Preserve the user's test limits; a request for minimal checks or no local packaging permits source/manifest checks, not a local archive or executable build. Formal artifacts follow the project's release workflow.

Read [acceptance](references/acceptance.md) for package inputs, relocation or lifecycle evidence. Select checks by the changed behavior; do not create a universal build framework or force GUI dependencies into CLI packages.

Read [version and Tag strategy](references/version-tags.md) only for requested Tag policy, a version checkpoint or authorized Tag delivery. Daily commit/push can proceed through applicable project instructions without loading a release procedure.

Report files, source identity, actual check results and remaining platform acceptance. Parsing, archive creation, launcher success and real GUI interaction are different evidence. Release, installation and external writes require their own authorization.
