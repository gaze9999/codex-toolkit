# Task Guide

Create or refresh a feature-specific task guide from actual project evidence. Preserve requirements, work-item identity and any existing history workflow. Do not invent a stack, commands or completed validation.

For a requested Goal, Plan, sketch or review/test brief, read [planning and acceptance](references/planning-and-acceptance.md) and only the selected template. This prepares artifacts and routes to existing specialists; it does not start a Goal, delegate, run scans or authorize implementation by itself.

Read [workflow](references/workflow.md) for creating/updating guides, work-item IDs or history snapshots. It routes to the existing schemas, examples and scripts. Use only relevant modes, keep stable IDs and original sources, inspect side effects before executing helpers.

For explicit structured requirements or superseded decisions, read [decision records](references/decision-records.md). Keep specification requirements, confirmed user decisions and execution plans distinct; ordinary task continuation does not require a new persistent file.

For requirement-file boundaries, AI indexes, human reports, history retrieval or detail/summary choices, read [document views](references/documentation-views.md). Adapt existing records rather than creating a parallel documentation system.

Return the requested artifact or confirmed operation with actual evidence and concrete gaps. Do not confuse prepared content with execution, parsing with runtime adoption or an intended check with a completed result.
