# Operating efficiency

Use for an authorized workflow redesign or evaluation. Existing instruction-layering, delegation-routing and context-continuity references retain their authority; this reference adds distribution, budgets and measurement decisions.

## Sources and routing

- Keep durable rules at their smallest valid layer. Plugin catalogs map canonical Skill sources to generated packages; installed/cached copies remain mirrors. Package identity does not imply security isolation or host reload.
- Group Plugins by shared workflow, dependency lifecycle and useful enable/disable boundaries. Split a group when users need independent activation or a distinct trust/runtime boundary; do not split merely by role name or aggregate everything for a lower package count.
- Keep focused Skill descriptions discriminating: capability and invocation condition, plus exclusions only for likely collisions. Separate implementation from prompt-only work, build from acceptance-only work, and governance from routing operations. A task may legitimately need more than one Skill.
- Put common purpose and important constraints in SKILL.md, conditional mechanics in directly discoverable references, repeatable deterministic transformations in scripts and copied output materials in assets. Avoid chained indexes when a direct conditional link is enough. File counts alone do not establish context or usage cost.

## Context, work and stopping

- Reuse facts/checks only for the relevant source state and environment. Pass source pointers and decisions that affect a worker's task, then let it inspect necessary raw evidence. Do not duplicate complete research logs, repository scans or transcripts.
- Use a deterministic filter for large repeated logs, tabular projections or changed-file selection when it materially reduces model input. Preserve an original evidence pointer, error, exit code and completeness indicator. Do a small search directly instead of creating a context-builder framework.
- For a task with possible unbounded work, agree on a useful stopping condition rather than inventing universal token/tool/agent quotas. Finish required acceptance. Reassess a search when new sources stop changing the conclusion, a retry when it brings no new evidence, and an owner/model escalation when the problem becomes ambiguous or exceeds its verified scope.
- Stop dependent work for missing authorization, decisions or environmental capability; continue independent authorized work. Higher reasoning and extra retries do not resolve missing permissions or a broken tool.
- Delegate only an independent slice whose context isolation or acceptance value exceeds coordination cost. Main handles small/coupled work and integration. Parallelism needs settled shared interfaces and isolated mutable resources. Do not claim usage savings from agent count alone.
- Select supported models by uncertainty and verification burden using effective configuration and explicit user choices. A cheaper model is useful for a bounded verified method only when repair/review costs remain acceptable. Escalate on conflicting evidence, repeated informative failures or expanded architecture/security scope; do not automatically inherit high effort everywhere.

## Minimal recipient-specific return

Prefer readable Markdown for humans and agents. Use typed JSON only when a tool or result merger actually consumes it. Omit irrelevant fields rather than filling every role's template.

| Recipient | Required useful content |
|---|---|
| Implementation owner | Status, changed behavior and every changed file, checked source state, actual validation, unresolved acceptance |
| Explorer/researcher | Answer/findings, exact source pointers, evidence qualifications and unresolved questions |
| Reviewer | Concrete severity/location/trigger/impact/evidence findings, inspected scope and validation gaps; no findings is valid |
| Test owner | Checked revision/environment, executed checks, results and failed/blocked/unverified criteria |
| Main's user | Outcome, every changed file grouped compactly when useful, real checks and material remaining work |

Main retains integration and acceptance. Return command/log details only for reproduction, a failure or provenance; avoid routine files_read/tool_calls inventories unless measuring them. A reviewer receives original requirements, relevant diff/code and test basis without an implementer's success narrative.

## Evaluate before claiming efficiency

- Use positive, negative and collision fixtures with recorded real Skill selections. Fixture/schema validity is separate from behavioral routing quality.
- Compare a fixed task set and acceptance protocol with paired before/after trials. Preserve revision, environment, model/effort, success/first-pass acceptance, validation, regressions, duration, tool/agent counts, retries and human corrections.
- Keep missing metrics null. Exact UTF-8 bytes, artifact sizes and file counts are proxies, not model tokens or ChatGPT/Codex quota. Only record provider/runtime usage when actually available. Avoid a composite score that conceals quality loss.
- Store only explicitly selected metadata with field allowlists; do not scrape source, chat histories, .env files or credentials for a routine benchmark. Local measurement does not authorize continuous collection or an external telemetry endpoint.
- Validate scripts and clean distribution independently of routing/quality tests. Test traversal, collisions, unsafe inputs, output ownership, source drift, reproducibility and actual readback. Install/reload, authentication and native platform checks retain separate evidence.
